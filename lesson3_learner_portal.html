🔧 Topic 3A: System and Network Architecture

📖 What is System and Network Architecture?

System and network architecture refers to the design of system components and network structures that together provide a secure and reliable environment for businesses and organizations.

It protects against both malicious attacks (hackers, malware) and accidental threats (misconfigurations, human error) through layered security.

System Hardening

📖 What is System Hardening?

System hardening is the process of securing an operating system, application, device, or service by reducing its attack surface — meaning fewer opportunities for attackers to exploit.

System Hardening Best Practices

  • Reduce Attack Surface: Run only necessary services, disable unnecessary features
  • Restrict Access: Protect system files, Windows registry, configuration files, and logs
  • Limit User Privileges: Apply the principle of least privilege
  • Apply Updates: Regular patching protects against known vulnerabilities
  • Add Monitoring: Use malware protection, intrusion detection, system monitoring
  • Maintenance Schedule: Continuous hardening through regular reviews

📌 Hardening Standards

DoD STIGs (Security Technical Implementation Guides): U.S. Department of Defense guidelines providing detailed configurations and best practices for securing systems, networks, and software.

CIS Benchmarks™: Widely recognized best-practice guides with detailed recommendations (e.g., over 1,200 pages for Windows 11 Enterprise).

Windows Registry and File System

📖 What is the Windows Registry?

The Windows registry is a database that stores operating system, device, and software application configuration settings. It organizes system-wide and user-specific information into root keys and subkeys.

Registry Root Key Abbreviation Description
HKEY_CLASSES_ROOT HKCR Stores file association details and OLE information. Determines which application opens a specific file type.
HKEY_LOCAL_MACHINE HKLM Governs system-wide settings (hardware, software, system configurations) that apply to all users.
HKEY_USERS HKU Stores settings for all user profiles on the computer. Each user's profile is a subkey under this root.
HKEY_CURRENT_USER HKCU A subset of HKEY_USERS with settings for the currently logged-in user (desktop, network, applications).
HKEY_CURRENT_CONFIG HKCC Contains current hardware configuration at startup. This key is temporary and disappears after shutdown.

Important Registry Files (Hives)

File Name Description
SAM Security Accounts Manager - stores user account information including hashed passwords
SECURITY Contains local security policy settings, user rights, audit policies
SOFTWARE Configuration data for installed software and applications
SYSTEM Settings for system startup, drivers, hardware profiles - critical for boot process
DEFAULT Default user profile settings for new user accounts
NTUSER.DAT Stored in each user's profile folder - contains all user configuration settings. Never delete!

⚠️ Registry Storage

Location: Most registry files are in C:\Windows\System32\Config

Hive Components: A hive typically includes:

  • A file with no extension (main storage)
  • A .LOG file (transaction log)
  • A .SAV file (backup copy at setup)
  • An .ALT backup file for recovery

Configuration File Formats

Format Description Syntax Common Use
INI Initialization file Key-value pairs with "=" Older Windows applications
XML eXtensible Markup Language Tag formatting like HTML APIs, structured data exchange
YAML Yet Another Markup Language Indentation and ":" Docker, Kubernetes, modern configs
JSON JavaScript Object Notation {} and [] for grouping Web services, JavaScript apps

Linux Configuration Files

  • Linux does not use a registry database like Windows
  • All configuration settings are stored in text files
  • Most config files are in /etc directory
  • May also appear in /usr, /opt, /var
  • Software applications rely on these config files for customization

System Processes

📖 What are System Processes?

System processes are background tasks that run on a computer automatically, often without user interaction or awareness. They are essential for the operating system to manage resources like memory, network connections, and hardware devices.

Role of System Processes

  • Run essential OS services in the background
  • Launch applications and handle user-level tasks
  • Maintain security and performance through monitoring
  • Manage system resources (memory, CPU, network)

📌 Examples of System Processes

  • Antivirus scans (background malware detection)
  • Disk defragmentation (optimizing file storage)
  • User authentication (verifying login credentials)
  • Printing services (managing print jobs)
  • System updates (downloading and installing patches)

Hardware Architecture

📖 What is Hardware Architecture?

Hardware architecture describes the underlying technology and design that a device uses to perform computational tasks.

Key Concepts

  • OS & Application Compatibility: Operating systems and applications are designed for specific hardware architectures
  • Architecture Characteristics: Different architectures emphasize scalability, processing power, efficiency, or power management
  • Common Architectures:
    • x86: Dominates desktops, laptops, and server computers
    • ARM: Popular in smartphones, tablets, and embedded devices like Raspberry Pi
  • Cross-Platform Limitation: Software built for one architecture cannot run on another without an emulator

📌 Architecture Examples

x86 Use Case: A Windows OS for x86 cannot run directly on an ARM device without translation/emulation. x86 systems are optimized for high performance (servers, gaming PCs).

ARM Use Case: ARM devices are optimized for low power consumption, making them dominant in mobile computing and IoT devices.

Virtualization

📖 What is Virtualization?

Virtualization is the process of creating virtual versions of computing resources (servers, storage, networks) that allow multiple systems to run on the same physical hardware.

Impact of Virtualization

  • Revolutionary Technology: Transformed IT infrastructure in ways unimaginable a decade ago
  • Cloud Adoption: Widespread use in public clouds has fueled innovations like containers, serverless computing, and microservices
  • Essential Capabilities: Understanding virtualization is critical to grasping modern IT infrastructure

How Virtualization Works

Virtual servers resemble physical servers with components like processors, storage adapters, memory, and other hardware. These components are managed similarly to physical servers. The key distinction is how hardware is presented to the operating system, facilitated by a hypervisor.

Benefits of Virtualization

  • Resource Sharing: One physical server can host multiple VMs, maximizing hardware utilization
  • High Availability: VMs can move between physical systems (live migration) with minimal downtime
  • Software-Defined Flexibility: Hardware components (CPU, memory, storage) managed via software
  • Scalability: Add or adjust resources on the fly, often automatically based on demand
  • Business Continuity: Supports disaster recovery and business continuity planning

Types of Hypervisors

Type Description Use Case Examples
Type 1 (Bare-Metal) Runs directly on hardware without a host OS. Purpose-built, lean, and efficient. Enterprise data centers, production environments VMware ESXi, Microsoft Hyper-V, Citrix XenServer
Type 2 (Hosted) Installed on top of a full-featured host OS. Easier to use with GUI support. Testing, development labs, desktop virtualization Oracle VirtualBox, VMware Workstation, Parallels Desktop

Application Virtualization

📖 What is Application Virtualization?

A software delivery model where the application runs on a server but is streamed to the client device. To the end user, the application looks and behaves as if it's installed locally.

Key Characteristics

  • Clients access applications hosted on servers
  • Application is streamed in real-time
  • Enables delivery without complex installation on each device
  • Often paired with HTML5 remote desktop apps (clientless solutions)
  • Users can access through standard web browsers

📌 Application Virtualization Solutions

  • Citrix XenApp
  • Microsoft App-V
  • VMware ThinApp

Containerization

📖 What is Containerization?

Application cell/container virtualization operates without a hypervisor and instead relies on resource separation at the operating system level. Each container runs within isolated "cells" with allocated CPU and memory resources.

Container Characteristics

  • OS-Level Virtualization: Processes use the native OS kernel
  • Application Isolation: Containers host separate application processes with required variables and libraries packaged inside
  • Efficiency: Lightweight compared to full virtual machines
  • Portability: Easily portable across development, testing, and production
  • Cloud Usage: Fundamental to cloud services, supports microservices and serverless architectures
Feature Virtual Machines (VMs) Containers
Guest OS Each VM has its own full OS Share host OS kernel
Size Heavyweight (GB) Lightweight (MB)
Startup Time Minutes Seconds
Isolation Strong (complete OS separation) Good (process-level)
Portability Less portable Highly portable
Use Case Different OS types, legacy apps Cloud-native apps, microservices

📌 Container Technologies

  • Docker: One of the most well-known container platforms
  • Kubernetes: Orchestrates and manages containers at scale

Serverless Computing

📖 What is Serverless Computing?

A modern design pattern where the cloud provider manages the infrastructure required to run applications. Applications run within virtualized runtime containers in the cloud rather than on dedicated server instances.

Serverless Characteristics

  • Reduced Management: No need to manage physical/virtual servers, patching, or admin privileges
  • Cloud-Driven Redundancy: All redundancy handled within the cloud (no need for multiple servers)
  • Pay-per-use Billing: Based on execution time, not hourly charges like VMs
  • DevOps Support: Enables rapid development and deployment
  • Event-Driven Orchestration: Services triggered by client connections

⚠️ Serverless Considerations

  • Security Concerns: Must ensure legitimate users aren't impersonated; strong authentication critical
  • Developer Accounts: Must be locked down with minimal tools
  • Evolving Best Practices: Constantly changing security landscape
  • Provider Dependency: Limited control over failures and disaster recovery

📌 Serverless Platforms

  • AWS Lambda
  • Google Cloud Functions
  • Microsoft Azure Functions

Software-Defined Networking (SDN)

📖 What is SDN?

Software-Defined Networking (SDN) replaces traditional network hardware functions with a virtual control plane that manages traffic. It separates the control plane (decision-making) from the data plane (traffic forwarding).

SDN Benefits

  • Segmentation: Divides networks into smaller, isolated subnetworks to enhance security
  • Flexibility: Quickly reprogram data flows and apply policies across entire network
  • Automation: Reduces manual configuration by automating deployment
  • Centralized Control: Monitor and adjust traffic through one virtual controller
  • Critical for Orchestration: Essential component of automation technologies

The Three Planes of SDN

Plane Function Responsibilities
Management Plane Administrators and monitoring • Monitors traffic conditions and network status
• Provides visibility, logging, and reporting
• Enables policy configuration
Control Plane Decision-making • Makes decisions on traffic prioritization and security
• Defines forwarding rules for data plane
• Provides centralized intelligence
Data Plane Traffic forwarding • Handles actual switching and routing of packets
• Enforces ACLs and security rules
• Executes instructions from control plane

📌 SDN Use Cases

  • Cloud data centers with thousands of servers needing automated traffic management
  • Incident response where malicious traffic must be contained within specific network sections
  • Dynamic scaling of resources for business continuity

Deperimeterization

📖 What is Deperimeterization?

The shift in security strategy where the traditional boundary between "inside" (trusted) and "outside" (untrusted) networks becomes less relevant. The perimeter has blurred, making perimeter-only defenses insufficient.

Trends Driving Deperimeterization

  • Cloud: Data and applications hosted outside traditional corporate perimeter
  • Remote Work: Employees connect from home networks or public Wi-Fi, bypassing corporate perimeter
  • Mobile Devices: Smartphones and tablets access corporate resources from anywhere
  • Outsourcing: Third-party vendors need access to internal resources
  • Wireless Networks: Wi-Fi is more open and harder to secure than wired networks

Zero Trust Architecture

📖 What is Zero Trust?

A security framework that eliminates the idea of a trusted internal network and an untrusted external network. Core principle: "Never trust, always verify."

Reference: NIST SP 800-207 "Zero Trust Architecture"

Zero Trust Principles

  • Everything is considered "outside" - no automatic trust
  • Trust Nothing, Validate Everything: All users, devices, and applications must prove identity
  • Continuous Verification: Re-check identity at every step, not just at login
  • Least Privilege: Only grant minimal required access
  • Micro-Segmentation: Break networks into small zones to limit lateral movement

Key Benefits of Zero Trust

  • Greater Security: All users, devices, and applications authenticated before network access
  • Better Access Controls: More stringent limits on who/what can access resources and from what locations
  • Improved Governance: Limits on data access and greater operational visibility
  • Increased Granularity: Users granted access to what they need when they need it

Essential Components of Zero Trust

  • Network and endpoint security
  • Identity and access management (IAM)
  • Policy-based enforcement
  • Cloud security
  • Network visibility
  • Network segmentation
  • Data protection
  • Threat detection and prevention

Secure Access Service Edge (SASE)

📖 What is SASE?

SASE (pronounced "sassy") is a cloud-delivered security and networking framework that merges wide area networking (WAN) with security services into one unified model.

SASE Characteristics

  • Simplification: Combines networking and security into single cloud-hosted service
  • Hardware Elimination: No need for dedicated hardware appliances
  • Advanced Features: IAM, secure web gateways, Zero Trust network access
  • Remote Management: Centralized control and policy enforcement
  • Integration: Unifies NAC, VPN, firewalls, and threat protection

Core SASE Security Features

  1. Identity and Access Management (IAM): Defines user rights, enables SSO, supports multiple IAM solutions
  2. Secure Web Gateways (SWG): URL filtering, content scanning, malware protection. Examples: Cisco Umbrella, Palo Alto Networks, AWS WAF
  3. Zero Trust Network Access (ZTNA): Monitors network activities, blocks unauthorized traffic. Example: Cisco AMP

📌 SASE vs Traditional Security

Traditional: Multiple point solutions (separate firewalls, VPNs, web gateways) requiring complex management

SASE: Unified cloud service combining all security and networking functions with centralized management

🔐 Topic 3B: Identity and Access Management (IAM)

📖 What is IAM?

Identity and Access Management (IAM) is a framework of policies, technologies, and processes designed to ensure that only authorized users can access specific resources at the right times and for the right reasons.

Key IAM Capabilities

  • User Identity Management: Establishes and manages digital identities for individuals
  • Authentication: Confirms user identity through credentials (passwords, biometrics, 2FA)
  • Authorization: Grants access based on roles and permissions
  • Single Sign-On (SSO): Log in once, access multiple applications securely
  • Auditing and Logging: Tracks user activity for compliance and security monitoring
  • Integration: Connects IAM with third-party apps and cloud services

IAM Benefits

  • Reduces risk of unauthorized access to sensitive resources
  • Enhances compliance with regulations (GDPR, HIPAA)
  • Simplifies user experience with centralized access (SSO)
  • Supports Zero Trust by enforcing strict authentication and least-privilege principles

Authentication Factors

The Three Authentication Factors

  1. Something You Know - Knowledge-based credentials
    • Examples: Passwords, PINs, security questions
  2. Something You Have - Physical items that prove identity
    • Examples: Smart cards, security tokens, mobile authenticator apps
  3. Something You Are - Biometric traits unique to the user
    • Examples: Fingerprint, facial recognition, iris scans, voice patterns

📌 Why Use Multiple Factors?

Improves Identity Assurance: Adds extra layers of security beyond just a password

Harder to Compromise: Even if one factor is stolen (e.g., password), attackers still need the second factor (e.g., token or fingerprint)

Example: Bank login requiring:

  • Password (something you know) +
  • Security token from mobile app (something you have) +
  • Fingerprint scan (something you are)

Authentication Methods

Method Description Security Level
Multi-Factor Authentication (MFA) Uses two or more of the three authentication factors. May include additional attributes like location or behavioral traits. ✅✅ Very Strong
Two-Factor Authentication (2FA) Uses two of the three authentication categories (e.g., password + smart card) ✅ Strong
2-Step Verification Uses an out-of-band mechanism to deliver a one-time code through a separate channel (SMS, phone call, push notification, email) ✅ Good (but vulnerable to interception)
Passwordless Authentication Eliminates passwords by using biometric factors or one-time codes. Cannot be easily shared, removes burden of remembering complex passwords. ✅✅ Very Strong
Single Sign-On (SSO) Allows users to authenticate once and access multiple systems or applications. Improves usability but poses risk if credentials are compromised. ⚠️ Convenient but risky alone

⚠️ SSO Security Consideration

Risk: If SSO credentials are compromised, multiple systems are exposed.

Best Practice: Combine SSO with MFA for stronger protection.

Privileged Access Management (PAM)

📖 What is PAM?

Privileged Access Management (PAM) is a framework of policies, processes, and technologies designed to protect privileged accounts (system administrators, root accounts, service accounts) from credential theft, misuse, or unauthorized access.

PAM Key Functions

  • Control: Restricts who can use privileged credentials
  • Secure: Stores privileged credentials in a secure repository or vault
  • Monitor: Tracks privileged account activity in real-time
  • Audit: Provides logs and reports for compliance and security investigations

📌 PAM Providers

  • BeyondTrust
  • CyberArk
  • Centrify

Federated Trust and Identity Systems

📖 What is Federation?

Federation allows different organizations or networks to trust each other's accounts, eliminating the need for multiple usernames and passwords across systems.

Key Federation Technologies

Technology Description Use Case
OpenID Authentication standard letting users log into multiple sites with one set of credentials (e.g., "Sign in with Google"). Users register once with an OpenID provider. Consumer web authentication
SAML
(Security Assertion Markup Language)		 XML-based protocol for exchanging authentication and authorization data. Uses HTTP/HTTPS and SOAP. Digital signatures applied for trust. Enterprise SSO, AWS integration
Shibboleth Federated identity system built on SAML, widely used in universities and public organizations. Redirects users to their identity provider for authentication. Academic/research institutions

📌 Shibboleth Process Example

A student accessing an external library database:

  1. Student requests access to Shibboleth-enabled site
  2. Site sends a SAML request
  3. Student is redirected to university identity provider
  4. Identity provider authenticates and sends SAML response
  5. Site grants access based on SAML data

Transitive Trust

📖 What is Transitive Trust?

A trust model that allows authentication services to accept each other's identity assertions and permissions. If Resource A trusts Resource B, and Resource B trusts Resource C, then Resource A also trusts Resource C.

Transitive Trust Characteristics

  • Defines relationships between authentication services
  • Commonly used in Active Directory between domains
  • Benefits: Simplifies user access across multiple systems
  • Limitations: Can create security risks since trust extends automatically

Cloud Access Security Broker (CASB)

📖 What is CASB?

A Cloud Access Security Broker (CASB) is enterprise security software that acts as a gatekeeper between users and cloud service providers. It enforces security policies, ensures compliance, and protects sensitive data across all types of devices.

CASB Functions

  • Enables Single Sign-On (SSO) and enforces access controls
  • Scans for malware and prevents rogue or noncompliant device access
  • Monitors and audits user and resource activity in cloud services
  • Prevents data exfiltration by blocking access to unauthorized cloud services from managed devices
Deployment Model Description Pros & Cons
Forward Proxy Positioned at the client network edge. Forwards traffic to the cloud if it complies with policy. ✅ Real-time inspection of traffic
❌ Users may bypass proxy; can cause performance bottlenecks
Reverse Proxy Positioned at the cloud network edge. Routes user traffic to cloud services with policy enforcement. ✅ No device configuration needed
❌ Only works if the cloud app supports proxy integration
API-based CASB Uses APIs to connect cloud services with enterprise systems. Example: If a user account is disabled locally, CASB enforces it in the cloud via API. ✅ Direct integration with cloud providers; effective for access and authorization
⚠️ Often combined with proxy models for comprehensive coverage

📌 CASB Vendors

  • Microsoft
  • Forcepoint
  • Trellix
  • CloudSOC CASB

🛡️ Topic 3C: Data Protection & Operational Visibility

Maintaining Operational Visibility

📖 What is Operational Visibility?

The foundation of effective security operations is visibility — being able to identify, contain, and protect all data within the organization. This allows security teams to quickly detect and respond to unauthorized access attempts, breaches, or potential threats.

Why Visibility Matters

  • Regulatory Compliance: Ensures compliance with security standards (GDPR, HIPAA, PCI DSS)
  • Correct Data Handling: Ensures data is properly classified and protected across the organization
  • Greater Control: Know who, when, where, and how resources are accessed
  • Rapid Detection: Quickly detect and respond to threats before they cause damage

Data Loss Prevention (DLP)

📖 What is DLP?

Data Loss Prevention (DLP) refers to technologies and processes designed to detect, monitor, and prevent unauthorized access, sharing, or movement of sensitive data.

Goal: Ensure sensitive information (personal data, credit card details, intellectual property) does not leave the organization without approval.

DLP Components

  • Policy Server: Defines and enforces rules for data classification (confidential, public, private). Logs incidents and generates reports.
  • Endpoint Agents: Installed on client devices (laptops, desktops). Enforce policies even when users are offline or outside the corporate network.
  • Network Agents: Deployed at network borders (firewalls, mail gateways). Inspect communications (emails, instant messages, file transfers).

How DLP Works

  1. Content Inspection: Scans data in motion (network traffic), at rest (databases, servers), and in use (endpoint devices)
  2. File-Cracking Process: Converts unstructured data (Word, PDF, emails) into a scannable format for classification
  3. Pattern Matching: Identifies sensitive data like SSN, credit card numbers, PII
  4. Blocking Unauthorized Transfers: Stops sensitive data from leaving via USB drives, email, or cloud uploads
  5. Cloud Integration: Works with APIs or proxies to monitor and enforce policies in cloud services (Office 365, Google Drive, AWS)

DLP Remediation Actions

Action Description Use Case
Alert Only Copying is allowed, but the system logs the incident and may alert an administrator Monitoring phase, low-risk data
Block User is prevented from copying/transmitting the file but retains access to it. Violation is logged. Sensitive data, prevent data leakage
Quarantine Original file access is denied. File may be encrypted in place or moved to quarantine area. High-risk data, potential malware
Tombstone Original file is replaced with a message explaining the violation and how the user can request release User education, policy enforcement

📌 DLP Use Cases

  • Email Systems: Block unauthorized sharing of sensitive attachments
  • USB & Removable Media: Prevent copying of confidential files to external drives
  • Cloud Storage: Enforce data handling policies in OneDrive, Dropbox, AWS, Google Cloud
  • Social Media & Messaging: Stop leakage of sensitive info via chat or posts
  • Print Blocking: Prevent printing of classified documents
  • RDP Blocking: Prevent copying sensitive data over Remote Desktop Protocol sessions
  • Clipboard Privacy Controls: Restrict what can be copied to clipboard
  • Restricted VDI: Embed DLP controls inside virtual desktops
  • Data Classification Blocking: Prevent access based on sensitivity labels

Public Key Infrastructure (PKI)

📖 What is PKI?

Public Key Infrastructure (PKI) is a framework of tools, policies, and technologies used to manage public/private keys, digital certificates, and encryption.

PKI Functions

  • Manages Public/Private Key Pairs: Enables asymmetric encryption
  • Digital Signatures: Supports integrity checks and authentication
  • Certificate Management: Issues, renews, and revokes digital certificates
  • Non-Repudiation: Provides proof of origin that cannot be denied
  • Centralization: Makes it easier for organizations to meet compliance requirements
  • Identification: Uses digital certificates issued by Certificate Authority (CA) to verify identity

📌 PKI in Action: HTTPS

Digital certificates form the backbone of HTTPS, ensuring secure communication across the internet:

  1. You visit a secure website (e.g., your bank)
  2. Browser receives a digital certificate from the website
  3. Browser verifies the certificate was issued by a trusted Certificate Authority
  4. If valid, browser displays a padlock icon and establishes encrypted connection
  5. All traffic is encrypted using the public key from the certificate

SSL/TLS Inspection

📖 What is SSL/TLS Inspection?

The process of inspecting encrypted HTTPS traffic. SSL is the older protocol, replaced by TLS.

Why Inspect HTTPS Traffic?

  • Hidden Threats: Without inspection, attackers can hide malicious activity inside encrypted traffic
  • Certificate Validation: Prevents man-in-the-middle (on-path) attacks
  • Detect Malicious Certificates: Identifies traffic encrypted with untrusted or fake certificates
  • Policy Enforcement: Ensures employees comply with acceptable use policies (blocking restricted sites or file uploads)
  • Visibility: Provides visibility into restricted content access or data sharing

⚠️ SSL/TLS Inspection Process

  1. A digital certificate is installed on end-user devices
  2. Encrypted traffic is intercepted by a proxy, load balancer, or firewall
  3. Traffic is decrypted and inspected by security tools
  4. If clean, traffic is re-encrypted and forwarded to destination

Tools that support SSL/TLS inspection: Web proxies, load balancers, next-gen firewalls

Logging Concepts

Log Ingestion

📖 What is Log Ingestion?

Collecting log data from multiple sources (authentication servers, application servers, web servers, databases) and storing them in a central location for simplified analysis.

Log Ingestion Benefits

  • Provides comprehensive view of infrastructure activities
  • Helps in monitoring, auditing, and detecting threats
  • Common platforms: Splunk, Logstash, ELK Stack collect, normalize, and process logs

Time Synchronization

📖 What is Time Synchronization?

Ensures all systems have accurate and consistent time for logs. If system clocks are not in sync, event correlation becomes difficult.

Time Synchronization Methods

  • NTP (Network Time Protocol): Common method for syncing system clocks
  • Atomic clocks or GPS-based time sources: For highly accurate environments
  • Benefit: Establishes clear event timeline, essential in incident response and forensics

📌 Why Time Synchronization Matters

Scenario: Investigating a security breach

Without time sync: If the server clock is 10 minutes fast, the timeline is wrong - you can't determine the attack sequence

With time sync (NTP): All logs show accurate timestamps, you can trace the attacker's steps chronologically

4 Warning (warn) Warning condition (e.g., disk space low)
5 Notice (notice) Normal but significant (e.g., config change)
6 Informational (info) General information (e.g., service started)
7 Debug (debug) Debugging messages for troubleshooting

Why Logging Levels Matter

  • Helps filter logs (analysts may only want to see WARNING and above)
  • Prioritizes incident response (critical events get handled first)
  • Reduces noise by categorizing messages based on importance

📌 SIEM Platforms

SIEM (Security Information and Event Management) platforms are used for log management, analysis, and real-time threat detection:

  • Elastic SIEM
  • Splunk
  • IBM QRadar
